# DSH Patrick

面向 DSH 的 Windows 桌面模型网关，使用 Rust、Tauri 2、React、TypeScript 和 Vite 构建。当前版本 **0.1.18**。

本项目不是 DSH 或 DeepSeek 官方产品。界面布局和部分图标参考 [cursor-byok](https://github.com/leookun/cursor-byok)，不包含其 Cursor 专用接管、证书安装、广告或更新器。

## 功能

- 在桌面界面管理多个模型、API 地址、API Key、自定义请求头和额外 JSON 参数。
- 支持 OpenAI Chat Completions、OpenAI Responses 和 Anthropic Messages；按配置协议转发，不做协议互转。
- 获取上游模型列表、单模型测试、批量测试（最多并发 3）、取消和测试结果详情。
- 每个模型单独启用注入提示词；新模型默认关闭。提示词上限 128 KiB，按 UTF-8 字节统一计数；错误明确指出字段、实际大小和上限。推理强度留空时保留客户端设置。
- DSH 自动接入：新增本项目自己的 provider，同步启用模型，不替换原 provider 或强制切换会话默认模型。
- 断开网关时撤销本项目写入的配置；接入前备份，遇到外部冲突会报错而不是覆盖。
- Token 趋势、活动热力图、调用记录和按来源筛选的统计。
- 周/月趋势按本地自然日分组，日内按整时段分组；横轴与实际柱子对齐，悬停显示准确起止时间。自定义范围保留秒及毫秒，按开始含、结束不含筛选；日历月份对齐实际周列。
- 系统设置：四类 Token 单价、手动检查更新、当前用户开机启动及统计存储清理。
- 浅色、深色和跟随系统主题；关闭窗口收起到托盘，真正退出使用托盘菜单。

## 初次使用

1. 启动 Windows 桌面程序，在模型页添加自己的服务器地址、模型 ID 和 Key。仓库不附带可用的账户或个人模型配置。
2. 在「DSH 接入」中手动填写实际使用的 DSH profile 目录（例如数据目录下的 `profiles/web` 或 `profiles/desktop`），然后保存路径。软件不自动扫描或选择目录；已保存路径原样保留。
3. 在 DSH 模型页打开网关开关。默认本机地址为 `http://127.0.0.1:8787/v1`，端口可调整。
4. 回到 DSH，在 **DSH Patrick** provider 下选择模型。上游 Key 只保存在 Patrick；写入 DSH 的是独立本机令牌。
5. 使用「断开」或托盘退出恢复本项目管理的配置。窗口右上角的 × 只是隐藏窗口。

交付包自带 Node.js 接入运行时，YAML 解析器已打包进 Patrick 的接入组件，不从目标 profile 加载依赖或运行 DSH 插件。请完整解压便携包，保留 EXE 旁的 `runtime/node.exe`；用户无需另外安装 Node.js 或给 DSH 补装 YAML。软件仍核对用户指定配置的结构，未知格式保留原文件并报告原因。获取模型列表和点击测试会访问你填写的服务商，并可能产生服务商用量。

### Zen 请求头

- 模型编辑中的 Zen 开关仅用于网关自己的测试按钮。开启时测试输出预算为 20,000 Token，不修改模型保存的输出上限或正常 DSH 请求；高级 Extra 参数仍按原有优先级处理。
- 一次独立测试生成一个会话 ID；同次重试复用，新的独立测试重新生成。
- 正常代理流量不使用测试 ID；客户端的有效 `x-opencode-session` 优先于模型静态配置。
- DSH 长期会话头由 DSH 及其插件处理，测试按钮不会替换 DSH 用户会话。
- HTTP 200 不直接视为成功；测试会核对实际文本输出、流终止和上游错误。

## 参数与路由

- 模型列表：`GET /v1/models`。
- Chat：`/v1/chat/completions`；Responses：`/v1/responses`；Anthropic：`/v1/messages`。
- 默认填写 API 根地址；勾选「完整请求地址」后使用指定端点。
- 自定义 Headers 和提示词分别受各模型开关控制。关闭开关保留编辑内容，但不发送。
- 额外参数为 JSON 对象；模型、消息、地址、鉴权等保留字段受到校验。
- 模型设置留空不等于强制覆盖客户端值。显式模型设置可能覆盖同名客户端参数。
- 本机入口需要独立网关令牌，不接受把上游 Key 当成本机令牌使用。

### 并发与排队

- 系统设置可保存请求体处理并发（1–16，默认 16）和模型转发并发（1–32，默认 32）；旧配置自动补齐默认值。
- 所有模型共享转发额度，获取模型列表和测试按钮也计入；流式回复结束或取消后释放名额。
- 两阶段满额后按 FIFO 等待，每阶段最多 128 个等待者；队列已满返回 429，排队超时返回 504。
- 两阶段共用从请求进入处理流程起计算的排队时间预算，沿用「排队 / 非流式超时（秒）」。获得转发名额后的等待预算单独计算。客户端自身可能更早超时。
- 接收阶段的名额保留到获得转发名额，避免大量已解析的大请求在队列里积压。16 个 64 MiB 请求仅原始内容就可能达到 1 GiB，JSON 等结构还会额外占用内存；长上下文场景可调低请求体并发或大小上限。
- 修改并发数须等待网关空闲（包含排队请求）；保存后立即生效，无需重启 DSH。其他设置仍按原有规则保存。
- 这不提高上游服务商的配额，也不保证真实模型的吞吐量。

## 数据与隐私

### 定价、应用与存储设置

- Token 定价是首页估算使用的统一美元单价（每百万 Token），四项默认留空，0 表示免费；不是服务商账单，也不向模型请求附加价格。
- 估算遵循当前时间与来源筛选。缓存 Token 从输入总量扣除，避免重复计费；未上报缓存拆分时按普通输入估算。缺失输入/输出用量或所需单价时不计入金额，首页显示估算覆盖条数。
- 开机启动仅管理当前 Windows 用户的 `DSH Patrick` 启动项，指向当前便携程序路径；登录后打开软件，不自动接管 DSH。移动便携目录后应重新设置启动项。
- 检查更新仅在点击时匿名访问本项目 GitHub Releases，不携带模型凭据，不自动下载或安装。仓库未公开、无发布或网络失败会明确提示，不视为已经是最新版。
- 清理存储空间须二次确认，仅清空加密统计历史、持久调用记录、请求响应详情和测试结果。模型、Key、软件设置与 DSH 配置保持不变；有活跃/排队请求时须等待结束。
- 浏览器预览不操作 Windows 启动项、发布页或本机存储。

- 默认数据位于 EXE 同级 `app-data`，可通过 `DSH_PATRICK_DATA` 指定独立数据目录。
- Windows 当前用户 DPAPI 加密配置和统计历史。上游 Key、自定义头等仍属于敏感数据，加密文件同样不应提交或随发布包分发。
- DSH profile 内的 `.dsh-patrick` 保存私有备份，可能包含旧凭据，只留在本机。
- 默认不记录消息正文；“详细记录”开启后，对之后的模型测试及正式转发采集脱敏的请求和响应（各 128 KiB 上限）。内容可能包含对话正文，只保存在本机加密文件。测试预览始终只保留在内存。
- 模型测试使用合成短提示词，并保留该模型已启用的注入提示词、推理强度和自定义参数；不重放用户对话。
- 便携包升级时数据按目录隔离；不要以为复制新 EXE 到另一个目录会自动迁移原配置。
- 上游 HTTPS 验证证书；请求不跟随重定向，也不自动读取系统代理。

## 开发与构建

当前实现针对 Windows。需要 Node.js 24、Rust stable 的 MSVC 工具链、Visual Studio C++ Build Tools（含 Windows SDK）和 WebView2 Runtime。

在项目根目录运行：

```powershell
npm ci
npm run build
cargo test --locked --manifest-path .\src-tauri\Cargo.toml
node .\tools\statistics.test.mjs
```

开发桌面窗口使用独立数据目录：

```powershell
$env:DSH_PATRICK_DATA = Join-Path (Get-Location) 'app-data'
npm run tauri -- dev
```

生成 release EXE：

```powershell
npm run tauri -- build
```

未设置 `CARGO_TARGET_DIR` 时，EXE 位于 `src-tauri/target/release/dsh-patrick.exe`。目前关闭安装包生成。发布时先将新 EXE 复制到一个干净目录，再执行 `tools/package-runtime.ps1 -Destination <该目录的绝对路径>` 附带经核验的官方 Node.js v24.15.0 和第三方许可证；发布包包含 EXE、runtime 和公开说明，不复制任何 `app-data`。升级现有目录时保留原数据文件，不创建空配置覆盖它们。

`npm run dev` 单独启动的是浏览器界面预览，不具有真正的桌面网关能力。缓存位置可由 `CARGO_HOME`、`CARGO_TARGET_DIR` 和 `npm_config_cache` 自行指定；公开构建流程不依赖开发者的内部打包脚本或测试报告。

### 可选 DSH 集成测试

默认 Rust 测试及统计测试使用本机模拟数据，不调用真实上游。桥接与多实例恢复测试不再需要目标 profile 的 YAML；实际 DSH 插件协议集成仍需要以下显式环境：

- `DSH_PATRICK_DSH_SOURCE`：已构建 DSH 源码目录。
- `DSH_PATRICK_TEST_ROOT`：尚不存在的隔离测试目录，仅用于独立 Node bridge 测试。

```powershell
node .\tools\dsh-bridge.test.cjs
node .\tools\dsh-runtime.test.mjs
cargo test --locked --manifest-path .\src-tauri\Cargo.toml -- --ignored --nocapture
```

只在设置完上述依赖与隔离目录后执行；不要把真实 profile 作为测试写入目标。

### 调用记录与详情（0.1.7）

- 调用表格采用 36px 单行、33px 固定表头；默认 20 条/页，可选 50/100，支持首尾页及上一页/下一页，右侧详情按钮固定。
- 调用信息包含实际模型、最终 URL、思考强度、HTTP 状态、耗时、TTFB/TTFR/TTFT、Token、缓存和错误类别。未上报的字段显示“—”，不伪造 DSH Run/Conversation ID 或 Cursor 专用数据。
- 调用信息写入 `calls.dpapi`；详细模式开启时，请求与响应写入 `call-details/*.dpapi`。敏感请求头默认遮盖，结构化凭据字段及当前调用已知凭据值脱敏；对话中的其他隐私内容仍可能包含在详细记录中。不要上传 `app-data`。
- 每条详细请求/响应各最多 128 KiB，超出时显示未保存/截断提示，不截断实际转发。HTTP 非成功响应正文仍沿用原代理规则不读取，详情会显示 HTTP 和失败原因。
- 首次升级可从现有统计导入“旧版历史摘要”，只显示实际已有的时间、来源、状态、Token。旧版模型、耗时和正文未保存，保持未知。
- 清空调用记录不清首页统计；“仅清理详细内容”保留调用信息与统计；“清理全部统计数据”同时清调用、正文与统计，均不改模型、Key 或 DSH 配置。
- 系统设置按网关、流式超时、DSH 模型输出等待、并发与排队、外观及调用记录分别组织；数字设置独立编辑/取消/保存。详细记录默认关闭，保存后只对新请求生效。
- 本实现复用已有 DPAPI 存储，而参考项目使用 SQLite；对齐调用列表、详情、分页与持久化行为，不复制 Cursor 的会话和追踪机制。

## 流式超时（v0.1.10）

- 流式请求没有累计总时限，收到中转站数据或 SSE 心跳后重新开始下一次读取的等待。
- 系统设置 → 流式超时 · 中转站优先：无数据兜底基准 5–7200 秒（默认600），额外宽限1–60秒（默认10）；有效等待为两者之和，默认610秒。
- 等待响应头、响应体相邻两次数据读取分别使用此有效等待；15秒建连超时保留。下游消费造成的背压不当作上游空闲，不增加无限后台缓冲。
- 不接入账号切换事件，不自动读取中转站配置、不自动重放请求。换号期间如果中转站完全不发数据并超过兜底，仍会终止；心跳保持链路不等于正文成功。
- 完成仍须满足协议结束事件，HTTP200、只有心跳、流内错误、缺少结束标记都不当作完整成功。
- 原timeoutSeconds及现有值保留，仅控制排队及非流式请求总时间；新字段缺失时加载默认600+10，不改模型和鉴权。每个请求使用开始时的配置快照，新设置对新请求生效。

### v0.1.14 接入诊断

手动填写并保存 profile 后，点击“检查状态”会只读检查目录、必要文件、YAML 语法、模型配置、上层覆盖和凭据结构。页面分开显示目录检查、配置同步、客户端入口请求，不把保存路径或写入文件当作客户端已加载。检查失败自动展开明细，指出文件、配置项及处理建议；YAML 语法错误只显示行列，不回显正文或密钥。前置检查失败时，后续项目显示未检查。未保存的新路径不沿用旧结果；保存新路径后清除旧诊断。

检查遵守当前受支持的 profile 结构，不自动扫描或修改 DSH 文件。备份副本可能同样通过结构检查；入口标记不区分具体 profile，实际加载仍需用户在所用 DSH 选择 Patrick 模型并核对请求记录。自带 YAML/Node 的方案及原同步、备份、恢复机制保留。

### v0.1.15 Zen 请求兼容

- 正常转发只继承两个会话头：`x-opencode-session` 优先，空值时回退 `x-opencode-session-id`；有效值统一写入双头并覆盖静态值。双头不同但均有效时按主头统一并记录冲突；非法格式或同名重复值冲突返回明确400，不回显值。
- 保留与已适配插件一致的30字符校验和测试按钮降序时间编码。测试每次独立、重试复用；正常对话不生成测试ID。全局UA和三层鉴权保持不变。
- 新版插件使用精确 `providers/routes`：仅为可唯一确认的原模型追加 Patrick provider + 本地模型ID规则。跨provider同名歧义不猜测，会提示核对；已有用户规则保留。重复同步不重复，断开及停用仅撤销本项目追加项。旧插件的非空全局models配置保留旧方式；已迁移配置不再追加全局models。
- 兼容插件已迁移、Patrick 接入记录仍属旧版的状态：全局models已删除时不误报归属冲突，重新同步和断开均保留外部迁移后的providers/routes。
- 调用详情识别别名头并显示规范化/冲突状态；Zen正常流的空输出、SSE错误或截断不标记成功，工具输出仍算有效模型输出。非Zen流量沿用原结果规则。
- 入口格式错误仍直接返回400；补齐所有入口拒绝的调用记录仍属独立待办。DSH `streamIdleTimeoutMs` 设置已在 v0.1.17 增加。
- 可选新版插件隔离验证：设置 `DSH_PATRICK_ZEN_PLUGIN` 为已安装插件的 `lib/index.js`，指定新的 `DSH_PATRICK_TEST_ROOT` 后运行 `node tools/zen-compat.test.cjs src-tauri/src/dsh_bridge.bundle.cjs`。只导入纯函数并使用合成配置。现有 `dsh-runtime.test.mjs` 使用独立内存会话和本机mock，不读取真实profile或用户会话。

### v0.1.16 退出恢复与接入状态

- 接入标识区分未配置、待核对、未同步、已同步、核验失败和待恢复；与网关监听及历史客户端请求分开，不把核验失败写成“未接管”。
- 恢复配置失败时，停止开关、断开并恢复和托盘退出会提供明确确认选项。取消保持运行；选择保留配置后仅停止自己的本机网关（退出操作同时关闭软件），原 profile、凭据和接入记录保持现场，未完成恢复不冒充成功。
- 确认时再次检查正在执行和排队的请求，不强行中断。已失效的确认或改变后的 profile 路径不沿用旧确认；外部实例的接入仍不由本实例恢复。
- 本机加密待恢复提醒在下次启动保留；该 profile 成功同步或恢复后清除。保留的 Patrick 模型入口在网关停止期间不可用，需重新启动并完成接入处理。
- 包含 v0.1.15 Zen 双头和精确 routes 兼容，未更改模型请求、并发或超时机制。
